# 市場調査: 家計簿アプリ・カップル向け家計アプリの UX とカテゴリ体系

- 調査日: 2026-09-22
- 目的: pj_kakeibo（2人用・手入力・拠出額方式の精算）の設計判断に使う
- 方法: Web 検索と公開ページの閲覧（公式ヘルプ、ストア掲載情報、レビュー、第三者の解説記事）。一部の公式ヘルプ（MF ME、OsidOri、Monarch）は取得できなかった（403）ため、検索結果の抜粋と二次情報で補った。そうした箇所は「(二次)」と書く
- 表記: 【事実】= 出典に書いてあること、【推定】= 手順からの見積もり、【示唆】= このアプリへの提案

## 0. 要点（3行）

1. 大手2社はどちらも「大カテゴリ→中カテゴリ」の2階層（MF ME は支出の大項目16、Zaim は15）。サブスクは独立したカテゴリになっておらず、娯楽や通信に分かれて入る。2人の家計なら、固定費系を独立させた1階層12カテゴリで足りる。
2. 入力が速いアプリ（おカネレコ）の型は「金額（テンキー）→ カテゴリ → 記録」の3ステップで、それ以外の項目は主な動線から外している。
3. カップル向けアプリの精算で多い不満は「結局どちらがいくら払えばよいか分からない」こと。**矢印と金額**（例: 夫→妻 100円）で見せると伝わる。後から金額が決まる公共料金を「名前だけ先に登録し、精算時に金額入力を促す」機能は、主要アプリでは見つからなかった（差別化できる点）。

### 1.3 2社を比べて分かること

- 共通する骨格は「食・日用・交通・住まい・光熱・通信・医療/保険・衣服美容・娯楽・交際・教育・車・税・大型/特別・その他」の約15分類。
- 2人の共同生活の家計では、教育・税・車・現金/カードはほぼ出てこない（または別管理）。衣服・美容と医療は個人の支出になりやすい。
- 保険の扱いが2社で違う（MF は独立、Zaim は医療とまとめる）。家具・家電も「住まい」「特別/大型」と置き場所が揺れている。
- サブスクはどちらも独立していない。しかし2人暮らしの固定費では、動画・音楽・クラウドなどの割合が大きい。

設計メモ:

- 「食費」を食料品と外食に分けた。2社とも中カテゴリでは分けており、2人暮らしでは外食（デート代）が話題になりやすく、見直しの対象にもなるため。入力時は「お店で食べたかどうか」で迷わず選べる。
- 医療と服・美容は「その他」にまとめた（家計の支出だけを記録するという仮置きの前提では頻度が低い）。予備の候補は **医療 / 服・美容 / 車 / ペット / 子ども**。使ってみて「その他」が月の支出の 15% を超えるようなら、1つ入れ替える方針にする。
- カテゴリは中カテゴリを持たない。代わりに、自由記述の「メモ（任意）」と固定費の「名前」で細かさを補う。

## 3. カップル・夫婦向けアプリ:「共有」「精算」「誰が払ったか」の見せ方

### 3.1 アプリ別

| アプリ | 共有の仕組み | 誰が払ったか・精算の見せ方 | うまくいっている点 | 不満・課題 |
|---|---|---|---|---|
| OsidOri | 「家族ホーム（共有）」と「個人ホーム（非公開）」に分ける。共有したいお金だけを共有する | 取引ごとに割り勘・精算ができ、1件ずつでもまとめてでもよい。未精算の取引を貯めておき、月末にまとめて精算。分担割合や金額指定の変更、精算の取り消しもできる（FAQ の見出しより） | 取引を1タッチで家族/個人に振り分けられる。各人の負担額と差額が分かる | 精算で「どちらがいくら払うか」を明示してほしいという要望があった（例: 差額200円より「夫→妻 100円」の表示が欲しい。開発側は対応済みと回答）。料金が高め、無料版の制限、カード明細までの画面の遠さ |
| Zaim ペア家計簿 | 各自が自分のアカウントのまま、共有したい連携先だけを選ぶ（初期状態は共有しない）。相手のデータは閲覧のみ。プレミアム必須 | 精算機能の記述はない。「見える化」に限られる | パスワードを共有せずにプライバシーを保てる | 精算は別の手段が必要。同じアカウントを2人で使う方法もあるが、誰が入力したか分からず、全部見える |
| Warikani | 2人専用。1つの家計を2人で共有し、自動で同期 | 支出ごとに比率（例: 7:3）を指定し、精算時に「どちらがいくら」を表示 | シンプル。月末の精算だけで済み、ストレスが減ったという声 | 入力時の通知がほしい。自動生成の猫アイコンで2人を見分けにくい。広告が増えた |
| Splitwise | グループ / 2人の間の貸し借り台帳 | 「Paid by [you] and split [equally]」という文型で入力。残高は緑 = もらう側、オレンジ = 払う側。Settle up は「支払いの記録」で、削除すれば取り消せる | 分け方の柔軟さ。複雑な立て替えも清算しやすい形にまとまる | 債務の簡略化（Simplify debts）は多くの人を混乱させているとスタッフ自身が述べている。「誰にいくら」が支出一覧の陰に隠れている。無料版は1日の入力件数制限と広告 |
| Honeydue（米） | 口座ごとに共有範囲を選べる | 請求書のリマインダーに支払担当者を割り当てられる。取引に絵文字やコメントを付けられる | 2人とも支払日前に通知を受け取れる。取引の上で会話できる | 請求額を「今回だけ」変えられない（恒久的な変更しかない）。カテゴリが足りない。同期が遅い |

### 3.2 共通して見えること

- **精算の見せ方**: 「差額」や「残高」だけでは伝わらない。**向き（誰から誰へ）と金額**を1行で示すと伝わる（OsidOri の要望と対応）。
- **複雑さへの警戒**: 精算の計算を賢くするほど理解されなくなる（Splitwise）。
- **プライバシーの懸念**: 「個人の出費まで見られたくない」という声は多い。各アプリは個人ページや共有範囲の選択で対応しているが、画面や設定が増える原因にもなっている。
- **入力の偏り**: 手入力型では作業が片方に偏りやすく、それが不満になりやすい。
- **課金・広告・制限への不満**が目立つ（Splitwise、Warikani、OsidOri）。機能への不満より多いほど。
- **日本の共働き世帯の実務**: 共通口座に「各自が決めた額」を入れる方法（収入が近い場合）と、「収入比率で入れる額を決める」方法（収入差がある場合）が一般的に紹介されている。アプリの多くは「支出ごとの割り勘比率」で精算するが、pj_kakeibo の「拠出額を先に決める」方式は、この口座運用をそのままアプリにした形に近い。

## 4. 固定費・公共料金（金額が後で決まるもの）の扱い方

| パターン | 内容 | 採用例 | 限界 |
|---|---|---|---|
| A. 固定額の自動記録 | 支出/収入/振替を、毎日・毎週・毎月・毎年の頻度と日付を指定して自動で記録する | Zaim、MF ME の繰り返し入力 | 同じ金額が前提。変わる金額の扱いは記述がない |
| B. 予定の一覧＋支払済みチェック | 今月の予定を「予定 / 完了」に分けて、カレンダーと一覧で表示。支払われると緑のチェック。想定と違う金額で払われると黄色のチェック（二次）。3日前に通知 | Monarch | 口座連携での自動照合が前提 |
| C. 予定を今すぐ登録して金額を直す | 予定の支出を今すぐ登録できる。編集は「今回だけ / 以降すべて」を選べる | YNAB（scheduled transactions） | 金額が決まっていないことを示す状態はない |
| D. 担当者つきのリマインダー | 請求ごとに支払担当者と期日を持たせ、2人に通知 | Honeydue | 「今回だけ金額を変える」ができないという不満 |
| E. カテゴリ単位の固定/変動の区別 | 大項目ごとに固定費か変動費かを決め、予算で使う | MF ME | 個々の請求は管理しない |

分かったこと: 「名前だけ先に登録しておき、金額が決まったら入れる。月末の精算時にまだ入力されていないものを促す」という流れを明示的に持つアプリは、調べた範囲では見つからなかった。既存アプリは、固定額の自動記録（A）か、口座連携での照合（B）が中心。

【示唆】このアプリでの型（A + B + C の組み合わせ）:

1. 固定費を「ひな形」として登録する: 名前、カテゴリ、支払元、金額（**「毎月同じ」か「毎回入力」**のどちらか）、支払日（任意）。
2. 毎月1日（JST）に、その月の分を「予定」として自動で作る。金額が決まっているものはそのまま確定し、「毎回入力」のものは **金額待ち** の状態になる。
3. 金額待ちは入力タブと精算タブの両方にバッジで出し、タップするとテンキーが開く（入力は金額だけ）。
4. 精算を始めるときに金額待ちが残っていれば、まずそれを片付ける。各行で「金額を入れる」か「来月に回す」を選ぶ。
5. 金額の変更は「今月だけ」を既定にし、「以降も」は選んだときだけにする（Honeydue の不満への対策）。

## 5. このアプリの設計への示唆（10個）

1. **精算は「共用」を中心にした2本の矢印で見せる。** 「まさと → 共用 12,300円」「共用 → パートナー 4,100円」のように、人ごとに向きと金額を1行で示す。人と人の間の貸し借りや差額は表示しない（OsidOri の要望、Splitwise の混乱）。
2. **支出ごとの割り勘比率を入力させない。** 負担は月単位の拠出額で決まるので、支出の入力は「金額・カテゴリ・支払元」だけで済む。Warikani や Splitwise より入力項目が1つ少ないことを強みとして打ち出す。
3. **入力はテンキー先行＋1階層・12カテゴリのグリッド＋保存。目標は「金額の桁数 + 2タップ」**（おカネレコ水準）。大→中の2段階選択は作らない。
4. **支払元は文型の既定値にする。** 「まさとが払った」を既定（ログイン中の人）にし、その語をタップすると「共用 / パートナー」に切り替わる。日付は今日を既定にし、昨日・一昨日を1タップで選べるようにする（Splitwise の文型、Zaim の既定値）。
5. **固定費系のカテゴリを独立させる**（住まい・光熱費・通信・サブスク・保険）。大手2社でサブスクの置き場所がばらついている点を直し、固定費の一覧とカテゴリを 1:1 で対応させる。
6. **後から金額が決まる固定費は「金額待ち」という1つの状態で扱う。** 月初に自動で予定を作り、バッジで知らせ、精算時には「入力 / 来月に回す」の2択にする。金額の変更は「今月だけ」を既定にする。この機能は他のアプリにほぼないので、差別化の中心になる。
7. **共有範囲の設定を作らない。** 「家計の支出だけを記録する」という前提にすれば、OsidOri の個人ホームや Zaim の連携先選択のような共有範囲の UI が不要になり、タブと設定が減る。この前提は仕様とオンボーディングの1行で明示する。
8. **精算の完了は「記録」として残し、取り消せるようにする。** Splitwise の Settle up と同じく、完了した月はロックする。ロックの解除は精算タブの中で1操作にし、日常の削除や編集は確認ダイアログではなく Undo のスナックバーにする（NN/g、Material）。
9. **相手の入力に気付けるようにするが、通知は足さない。** 誰の記録かは色つきのイニシャルのアバターで一目で分かるようにする（Warikani の猫アイコンは見分けにくいという声がある）。ホームに「パートナーが3件追加」程度の差分を出すだけにする。コメント・絵文字・チャット（Honeydue）は入れない。
10. **機能を足さずに、広告なし・件数制限なし・起動するとすぐテンキーを保つ。** 不満の多くは課金・広告・制限・連携の遅れに集中している。口座連携、レシート読み取り、予算、多段階のグラフは入れない。PWA のホーム画面追加とセッションの長期保持で、起動したら入力画面が開くようにする（Zaim のショートカット、おカネレコのログイン不要の起動）。
