## 1. ユーザーの要件（原文の要約）

まさととパートナーの2人で使う、家計管理のアプリ。スマホ専用。

| # | 要件 |
|---|---|
| R1 | 2人がそれぞれ自分の ID とパスワードでログインする。相手の記録も見られる |
| R2 | 支出を「いつ・誰が（支払元: まさと・りさこ・共用）・何に・何円」で記録する |
| R3 | 毎月の固定費を扱う |
| R4 | 金額が後で分かる固定費（公共料金など）は名前だけ登録しておき、精算のときに金額を入れるよう促す |
| R5 | 精算額_i ＝ 出す額（拠出額）_i − もう払った分（立替額）_i。正なら個人 → 共用、負なら共用 → 個人。共用の過不足 ＝ Σ出す額 − 支出合計 |
| R6 | 出す額は月ごとに「手取り × 割合」で決める。割合は各自が持つ |
| R7 | タブごとの責務を分ける |
| R8 | 認知負荷を極限まで下げる |

- 基盤でユーザーが決めることは **05 §9（P1〜P5）**、初回デプロイで確かめることは **05 §8**。

## 4. スコープ外（MVP で作らないもの）

「作らない」と決めたもの。足すなら仕様書 §2.4 の置き場所に置き、§0.6 のチェックリストを通す。理由は仕様書 §2.4・§11。

| 作らないもの | 理由・メモ |
|---|---|
| 月ごとの推移グラフ | 月をまたぐ問いで、どのタブの問いにも答えない。タブの枠4つは 記録・支出・精算・設定 で使い切ったので、足すなら支出タブの内訳（S-13）の中 |
| 予算 | 要件に無い。比べる数字が増える |
| 人での絞り込み・人ごとの合計・件数 | 人どうしを比べる数字にしない（P10）。精算の内訳にだけ「もう払った分」を出す |
| 人から人への精算・支出ごとの割り勘比率 | お金はいつも共用を通る（P1）。負担は月の出す額で決まる |
| 記録の書き出し（CSV）・検索 | 月の切り替えと一覧で足りる |
| 通知（Web Push） | 気づくのは精算タブの赤い点と支出タブのお知らせ行だけ。iOS はホーム画面に追加したときしか使えない（確定 2026-09-23・仕様書 §12.1 Q17） |
| レシート読み取り・口座連携 | 入力を増やさず、連携の遅れを持ち込まない |
| コメント・リアクション | 相手を指摘する道具にしない |
| カテゴリの追加・名前の変更 | 15個で固定。「その他」が月の15%を超えたら1つ入れ替える |
| 共用口座の残高・累計 | 共用口座の残高そのものは扱わない。その月の過不足だけを出す（確定 2026-09-23・仕様書 §12.1 Q14） |
| 収入の記録 | 扱うのは月ごとの手取りだけ（出す額を決めるため） |
| 新規登録・メールでのパスワード再設定 | サインアップ OFF。忘れたらオーナーが再設定する |
| リアルタイム同期 | 開き直し・タブの選び直しで取り直す |
| 精算・ロックの操作のオフライン保留 | 2台の操作がぶつかるのを防ぐ（記録の追加だけ保留する） |
| 毎月の支払いの支払日 | その月の1日付けにする（仕様書 §12.2 Q16） |
| 削除した記録の跡 | 6秒の元に戻すの後は残さない（確定 2026-09-23・仕様書 §12.1 Q13） |
| PC 向けのレイアウト・3人以上・複数の家計 | スマホ専用、2人で1つの家計 |

## 5. 受け入れの目安

- **初日テスト**（仕様書 §0.6 の8）: 説明なしで、パートナーが6つの課題を1回でこなせること（記録する、昨日まさとが払った支出を見つけて開く、消して元に戻す、共用へいくら入れるか答える、その理由を言う、精算中の月で「入れた」を押す）。モックでも実装でも同じ課題で確かめる。
