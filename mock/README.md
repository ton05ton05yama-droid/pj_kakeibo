# モック（mock/index.html）

## 目的

- **UI の正本の片割れ。** `docs/03_ui_spec.md`（以下「仕様書」）と2つで1つの正本で、画面ID・状態名・文言・見本データを一致させる（仕様書 冒頭・§10）。
- 実装の前に、2人の画面・月の状態・精算のケースを実物に近い形で触って確かめるためのもの。受け入れの目安は仕様書 §0.6 の初日テスト（6課題）と §0.5 の上限表。
- アプリの部分は仕様書のトークン（§7.1）と文言（§1.3・§1.4）だけで作る。色合いは参考UI（pj_income_visualization）にそろえた白い地のライトだけ（仕様書 §3.9）。レビューのための操作はすべてスマホの枠の**外**のパネルに置き、アプリの画面に要素を足さない。
- 画面ID・状態キーの一覧は仕様書 §4.0.1、シナリオごとの期待値は仕様書 §9.8 が正本。このファイルにはモック独自のこと（開き方・URL のハッシュ・画面へジャンプ・端末の大きさの保存）だけを書く。

- 公開版（Artifact）の URL: https://claude.ai/artifact/N3jt4vwZnXuhPVCc9hsakz（`README.md`・05 §5.3 と同じ URL。更新は同じ URL に再公開する。**2026-09-23 の変更〈記録タブ化・S-04・カテゴリ15個・設定の「記録の払った人」・月の途中でも精算できる〈S-20 の［この月を精算する］〉・呼び名「りさこ」／ ID `risako`・給料の入り先〈S-33〉と出す割合を本人だけに・出す額を決め直したときは給料の入り先だけいまの設定を取り込む〈仕様書 §12.1 Q27〉・日付選択の「リセット」で今日に戻す〈同 Q28。2026-10-03〉・毎月の支払いの開始月と変更の履歴〈S-32・S-35。同 Q29〜Q31。2026-10-03〉・直すときの「何月分から」〈同 Q32・Q33。2026-10-03〉〉は未反映。05 §5.3**）
- フォント（Noto Sans JP）は Google Fonts から読む。オフラインでは代わりのフォントになる。

## URL のハッシュ

同じ画面を見てもらうために渡すもの（仕様書 §10.1。キー・読む順・例の正本はこの節）。操作するたびに書き直す。キーは次のとおり（テーマのキーは無い）。

| キー | 中身 |
|---|---|
| `s`・`st` | 表示中の画面ID・状態キー（見るためのもの。読むときは、`s` が S-01〈ログイン前〉と S-02〈閲覧者 `v` の初回〉のときだけ使う） |
| `v` | 閲覧者（`a` まさと ／ `b` りさこ） |
| `sc` | シナリオ（`sep-open` 〜 `sep-redo`。仕様書 §10.2） |
| `d` | 端末の大きさ（`375x548` など） |
| `case` | 精算ケース（仕様書 §6.3 の A〜L と **N**。N は9月の確定値に「りさこの給料は共用に入る」を重ねた合成。仕様書 §6.3 ケースN・§9.6 V11） |
| `tab` | タブ（`S-11` 記録 ／ `S-10` 支出 ／ `S-20` 精算 ／ `S-30` 設定 ／ `S-31` 毎月の支払い〈設定タブの中のページ〉）。無ければ `S-11`（記録タブ） |
| `m` | そのタブで見ている月（`2026-09`）。記録タブ・設定タブは月を持たないので、`tab=S-11` のときは読まない |
| `sh` | 開いているシートの画面ID |
| `sa` | シートの主な引数。S-04 はシートに出す年（`2026`。無いとき・4桁でないとき・選べる年の範囲の外のときは、そのタブで見ている月の年）、S-12 はカテゴリのキー（`groceries`・`entertainment` など）、S-14 は行のID、S-15 は行のID（`tab=S-20` なら、精算から開いた形〈1 / n と［次へ］〉で、その行の位置から開く）、S-22・S-33 は人（`a` ／ `b`）、S-32 はひな形のID、S-13・S-21 は月 |
| `j` | 画面へジャンプで来て、そのあと操作していないときの、ジャンプのキー（下の一覧） |

読むときの順: (1) `d` → (2) `case` があれば精算ケース、無ければ `sc` のシナリオ → (3) `v` → (4) `j` があり、そのジャンプのシナリオが `sc` と同じなら、ジャンプを実行して終わる。`s` が S-01 ならログイン前の画面、S-02 なら閲覧者 `v` の初回（呼び名を入れる画面）にして終わる → (5) それ以外は `tab`（無ければ記録タブ）・`m` をそのまま置き、`sh` があればふだんの開く操作（行を開く・S-22・S-21・S-32・S-33・S-34・S-13・金額待ちを開く）に `sa` を渡して開く。`sh=S-12` は記録タブのカテゴリから開くシートなので、開いたあとのタブは必ず記録タブになる（`tab` を一緒に書いても、見えるのは記録タブ）。S-12 の払った人の初期値は、閲覧者の設定「記録の払った人」（仕様書 S-30。見本データでは2人とも「自分」）で決まる。ハッシュには持たせず、`j=S-30:normal:joint` で共用にした形を渡す（日付と同じく、入力中の値は再現しない）。`sh=S-04`（月を選ぶ）は上部バーの年月から開くシートなので、`tab` が支出（`S-10`）か精算（`S-20`）のときだけ開く（記録タブ・設定タブは月を持たない。仕様書 §3.4・S-04）。マスの「いま見ている月」は `m`、選べる範囲は家計を作った月（2026-08）からシナリオの今月まで。S-12 の注記は、シートで選んでいる日付の月の金額待ちで決まる（支出タブで見ている月とは関わらない）。日付は入力中の値なのでハッシュでは再現せず、いつも既定の「今日」で開く。精算中の月の日付を選んだ状態は `j=S-12:action:lock` で渡す。閉じた月（精算中・精算済み）では S-21 を開かない。S-22 は、精算タブ（`tab=S-20`）で、S-20 がカードを出す状態（`estimate`・`ready`・`transfer`・`settled`・`redo`）のときだけ開く（例: `#sc=sep-prep&v=a&tab=S-20&m=2026-09&sh=S-22&sa=a` と `#sc=sep-open&v=a&tab=S-10&m=2026-09&sh=S-22&sa=b` では開かない）。

- りさこの初回ログインの S-01（ログインすると S-02 に進む状態）は、ハッシュでは作れないので、パネルの［りさこの初回ログイン］で作り直す。
- **月の途中の「精算のモード」（S-20 `estimate` の［この月を精算する］を押した状態）もハッシュでは再現しない**（保存しない画面の状態。仕様書 §12.1 Q2・§11 #45）。`sep-open`（9/22）の精算タブを開いて、その場で押して見る。タブを切り替える・月を切り替えると `estimate`（見込み）に戻るのも、そこで見る（この状態で URL をコピーすると `st=prep` ／ `st=ready` と書かれるが、`st` は読み取りに使わない書き出し専用のキーなので、渡された側には `estimate` が出る）。

例:

- `#s=S-20&st=ready&v=a&sc=sep-ready&d=375x548&tab=S-20&m=2026-09`（精算タブの9月）
- `#s=S-22&st=transfer&v=b&sc=sep-transfer-half&d=375x548&tab=S-20&m=2026-09&sh=S-22&sa=a`（りさこ視点でまさとの内訳を開いた状態）
- `#s=S-12&st=action&v=a&sc=sep-transfer&d=375x548&tab=S-11&sh=S-12&sa=groceries&j=S-12:action:lock`（記録タブから S-12 を開き、精算中の月の日付を選んだ状態。ジャンプで来た状態）
- `#s=S-04&st=normal&v=a&sc=sep-open&d=375x548&tab=S-10&m=2026-08&sh=S-04&sa=2026`（支出タブで8月を見ているところから、月を選ぶシートを開いた状態）

## 操作パネル

操作の一覧と、それぞれで確かめることは仕様書 §10.2（B9 の検査は §0.4 B9・§10.2）。モック独自のことだけをここに書く。

- 端末の大きさは localStorage に残る（既定 375×667）。
- 幅の狭い画面では、枠の上の「モック」のピルでパネルを開く。
- 初日テストは課題5のあと、自動で課題6の準備をする。

おすすめのレビューの順は仕様書 §10.3（まさと・`sep-open` で、開いた画面が記録タブであることを見てから記録〈k + 2〉→ 支出タブで行を確かめてりさこに替えて新着 → シナリオを順に進めて §9.8 と突き合わせ → 年月から S-04 を開いて8月へ（E6）→ 8月 → 精算ケース → 430×932 → 検査の重ね表示）。

## 画面へジャンプの一覧（ハッシュの `j`）

キーは「画面ID:状態キー」（仕様書 §4.0.1）。同じ画面・状態で見本が2つあるときだけ、3つ目の語を足す。
シートの `done`（閉じてトースト）はジャンプに無い。フロー（仕様書 §5）で見る。

- S-01: `normal` `empty` `action` `done` ／ S-02: `normal` `action` ／ S-03: `normal`
- S-04（月を選ぶ。**2件**）: `normal`（支出タブの8月から開いた形）／ `normal:settle`（精算タブから開いた形）。どちらも同じ部品で、違うのは移る先のタブだけ（仕様書 §2.3 E6）
- S-10: `normal` `action` `locked` `empty` ／ S-11（**記録タブ**。シートではなくタブのトップを開く）: `normal` ／ S-12: `normal` `empty` `action` `action:lock`（精算中の月の日付）／ S-13: `normal` `action`
- S-14: `own` `partner` `fixed` `locked` `unsent` ／ S-15: `normal` `empty` `action`（精算から 1 / 2）
- S-20: `estimate` `undecided` `empty` `prep` `ready` `transfer` `transfer:half`（まさとだけ入れた・りさこ視点）`settled` `settled:aug`（8月・ケースD'）`redo`
  - `estimate` では、固定部分の文字ボタン［この月を精算する］と、注記「金額待ち 2件を含みません」が固定部分に隠れないことを見る（仕様書 S-20 `estimate` の「縦の寸法」）。月の途中の `prep` ／ `ready` はジャンプに足さない（`estimate` から押して見る）
- S-21: `normal` `empty` `action`（空の欄があるまま押した）／ S-22: `ready` `estimate` `transfer`（まさとだけ入れた・りさこ視点でまさとの内訳）`settled`（9月・まさと）`redo`
- S-30（**2件**）: `normal`（記録の払った人が「自分」〈既定〉）／ `normal:joint`（「共用」に変えた形。そのあと S-12 を開くと払った人が［共用］で開く）／ `empty`（毎月の支払いが0件） ／ S-31: `normal` `empty` ／ S-32: `empty`（追加）`normal`（直す）`action` ／ S-33（**2件**）: `normal`（自分の行）／ `normal:salary`（自分の行・給料の入り先が共用口座）／ `partner`（相手の行。出す割合と給料の入り先が読み取り専用で「本人だけが変えられます」が出る。仕様書 §12.1 Q26）／ `action` ／ S-34: `normal` `action`

## 更新ルール

1. **仕様書と同じ変更で直す。** モックだけ・仕様書だけを直さない。順は モック → 仕様書 → 実装（仕様書 冒頭）。画面ID・状態名・文言・見本データを一致させる。
2. UI を変える前に仕様書 §0.6 のチェックリストを通す。上限（§0.4・§0.5）を超えるなら、何を削るかを先に決める。見送ったものは §11 に理由を書く（手順の全体は `CLAUDE.md` §2）。
3. 文言は仕様書 §1.3・§1.4 の表にあるものだけ。色・寸法は §7.1 のトークンだけ（参考UIに無い色を新しく作らない）。
4. 見本データを変えたら、検算パネルの **V1〜V11** がすべて ✓ になること（設定の「記録の払った人」を変えても、呼び名を「りさこ」にしても、月の途中で精算しても、**金額・件数・合計・精算額は変わらない**。仕様書 §9.1・§6.3 ケースM。**「給料の入り先」の既定は2人とも「自分の口座」**なので V1〜V10 の値も変わらず、共用にした月だけ V11 が効く。仕様書 §9.1・§6.3 ケースN）、仕様書 §9.6 と `docs/02_settlement.md` §9 の数字も直すこと。カテゴリを変えたときは、`CATEGORIES` の `key`（仕様書 §8 の内部キー）と見本データ・シナリオ・検算の期待値（EXPECT の `byCat`）をそろえること。
5. 直したら、検査の重ね表示・375×548 と 375×647 で確かめる。
6. **公開版（Artifact）を公開する。** まだ公開していなければ公開し、URL を `README.md`・このファイル・`docs/05_platform.md` §5.3 の3か所に書く。公開済みなら同じ URL に上書きする。
7. モックの操作パネルはレビューの道具で、アプリの仕様ではない。アプリの画面に操作を足さない。
